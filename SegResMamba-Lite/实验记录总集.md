## 0. 结论速览

1. **V10 = V2 骨干 + 唯一替换点（8³ Bottleneck 换成论文级 MoA）**：继承 V2 全部编解码器，删除 `mamba_8`，替换为 `MoABottleneckV10`（[v10.py#L176-L201](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L176-L201)）

## 2. 底层模块详解

### 2.1 LightResBlock——编解码基本单元（[v2.py#L16-L31](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v2.py#L16-L31)）

```
h = ReLU(IN(Conv3d_3×3×3(x → mid)))     # mid = min(in_ch, out_ch)，省参设计
h = IN(Conv3d_3×3×3(h → out_ch))
y = ReLU(h + shortcut(x))               # shortcut: 1×1×1 Conv（仅当通道/尺寸变化），否则 Identity
```

- 两次 3³ 卷积 + InstanceNorm（无仿射参数）+ 残差；瓶颈宽度取 `min(in,out)` 是参数量能压到 1.4M 档的关键之一

### 2.2 BiMambaLayer 与双后端（[v2.py#L34-L58](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v2.py#L34-L58)、[mamba.py#L195-L271](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/shared/models/mamba.py#L195-L271)）

- **双向机制**：`out = Mamba(x) + Mamba(flip(x, [D,H,W]))`——反向扫描通过空间三轴翻转复用**同一套参数**实现（不翻通道轴），无额外参数
- **单层 Mamba 内部**（[mamba.py#L254-L271](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/shared/models/mamba.py#L254-L271)）：3D 体素展平为序列 (B,C,D·H·W)→(B,L,C) → LayerNorm → SSM → 还原 → **残差 `out + x_skip`**
- **后端优先级**（[mamba.py#L199-L252](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/shared/models/mamba.py#L199-L252)）：`mamba_ssm.Mamba2`（CUDA）> MiniMamba（纯 PyTorch S6）> Mamba1CUDA > PurePyTorch
- **双口径警告**：日志实验（V9–V11）用 Mamba2SSM（Py3.12 + cu129）；本机当前回退 MiniMamba，参数量 +0.27%–0.99%，行为不可比——消融实验前必须确认 `MAMBA2_SSM_AVAILABLE=True` 或按设计文档 §2 做「锚点重跑」（[论文实验设计.md §2](实验记录总集.md)）

### 2.3 MoABottleneckV10——论文级 MoA（核心创新，[v10.py#L31-L173](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L31-L173)）

#### 2.3.1 子模块清单（dim=C=80，N=4，K=2）

| 子模块 | 结构 | 输出维度 | 参数量 | 作用 |
|--------|------|---------|-------:|------|
| `norm` | InstanceNorm3d(80)，affine=False | — | 0 | Pre-norm |
| `router` | Linear(80→4) | (B,L,4) | 324 | token 级路由打分 |
| `w_k` | Linear(80→40) | (B,L,40) | 3,240 | **共享** K 投影 |
| `w_v` | Linear(80→80) | (B,L,80) | 6,480 | **共享** V 投影 |
| `expert_qs[i]` ×4 | Linear(80→40) | (N_sel,40) | 12,960 | 专家 i 独有 Q 变换 |
| `expert_outs[i]` ×4 | Linear(80→80) | (N_sel,80) | 25,920 | 专家 i 独有输出投影 W_i^o |
| **合计** | | | **48,924** | 占全模型 ≈3.4% |

- 注意力缩放 `scale = (dim//2)^-0.5 = 40^-0.5`（[v10.py#L51](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L51)）——与打分维度 C/2=40 匹配
- 参数公式（后端无关，可精确复核）：`N·(C·C/2 + C/2) + N·(C·C + C) + (C·C/2 + C/2) + (C·C + C) + (C·N + N) = 4·3240 + 4·6480 + 3240 + 6480 + 324 = 48,924`

#### 2.3.2 前向流程（[v10.py#L85-L136](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L85-L136)，输入 (B,80,8,8,8)）

1. **Pre-norm + token 化**：IN → 展平为 (B, L=512, C=80)（[v10.py#L94-L96](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L94-L96)）
2. **token 级路由**：`router` 打分 → softmax 得 (B,512,4) → `torch.topk` 取 K=2 → 选中权重重归一化 `w/(Σw+1e-6)`（[v10.py#L99-L105](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L99-L105)）
3. **共享 K/V**：全图 token 一次性投影 `k=(B,512,40)`、`v=(B,512,80)`——所有专家共用，这是省参核心（[v10.py#L107-L109](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L107-L109)）
4. **token 级稀疏专家注意力**（逐专家循环 N=4 次）：收集选中专家 i 的 token 位置 `(b,l,k_idx)`；仅对这些 token 计算 `q_i = expert_qs[i](x_sel)`，与其**所属全图的 K/V** 做注意力（`scores = einsum('nd,nld->nl')·scale` → softmax over L=512 → `ctx = einsum('nl,nld->nd')`）→ `e_out = expert_outs[i](ctx)` → 按 Top-2 权重累加 `out_t[b,l] += w_i·e_out`（[v10.py#L111-L132](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L111-L132)）
5. **还原 + 残差**：unflatten 回 (B,80,8³)，`return out + x`（[v10.py#L134-L136](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L134-L136)）

> 关键语义：每个 token 的 query 只与**自己所属样本**的全局上下文（512 个 token 的 K/V）交互——专家是「全局上下文聚合器」，4 个专家因 Q 变换不同而学到不同的注意力模式；未选中的专家对该 token **不前向、无梯度**。

#### 2.3.3 与 SHMoAReg 公式对应

| 论文公式 | V10 实现 |
|----------|----------|
| `E_i(q_t,K,V) = Attention_i(q_t,K,V)·W_i^o` | `q_i = expert_qs[i](x_t)`（独有 Q）＋共享 K/V ＋ `expert_outs[i]`（独有 W_i^o） |
| `y_t = Σ_{i∈G(q_t)} w_{i,t}·E_i` | Top-2 选中权重（重归一化后）加权累加 |
| `G(q_t) = TopK(Router(q_t), k)` | `router = Linear(C→N)` 作用于 token 特征，softmax 后 topk |

- 实现级细节：路由器输入取 token 原始特征（每个专家的 q_i 由 `expert_qs[i]` 另行产生），即论文公式中 `Router(q_t)` 的输入以 token 特征实现
- 与标准多头注意力的区别：多头共享同一 Q/K/V 变换、各头只是投影切片；MoA 每个专家有**独立的 Q 变换与输出投影**，且经路由器稀疏组合——容量分配由数据端到端决定

#### 2.3.4 负载均衡损失（[v10.py#L156-L173](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L156-L173)）

- 对 (B,L) 取平均路由分布 `avg_weights (4,)`，与均匀分布 1/N 做 KL 散度（Switch Transformer 风格）
- 训练时经 `get_moa_load_balance_loss()` 取用（复用 forward 缓存的 `last_route_weights`，不重复前向），由 `frame/train.py` 按 `lb_weight=0.01` 加权进总损失（CLI 见 [train.py#L74](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/pipeline/train.py#L74)）；V9/V10 共用同一接口别名 `get_moe_load_balance_loss`（[v10.py#L281](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L281)）

#### 2.3.5 稀疏性与复杂度

| 配置 | 每 token 专家对数/例 | 相对计算量 | 语义 |
|------|:------------------:|:---------:|------|
| K=1（消融 B1） | 512 | 0.5× | 每 token 单专家 |
| **K=2（现行）** | **1,024** | **1×** | 效率–性能拐点（设计文档 §4-B 预期） |
| K=4（消融 B2） | 2,048 | 2× | 全专家激活 = token 级 soft MoA |

- 每对 (token,专家) 的开销 ≈ QK^T(512×40) + AV(512×80) + 两次投影；共享 K/V 只算一次/例
- 实现注记：逐专家 `nonzero` + gather 的写法对 N=4、L=512 的规模完全可行；`out_t[b_idx,l_idx] +=` 的累加是安全的（同一 token 的 Top-K 索引互不重复）

## 7. 设计动机与证据链（V10-v1 → V10-v2）

1. **失败起点（V10-v1）**：4 Mamba 专家 + 样本级 Top-2。全局 0.8894/5.05，LW 仅 0.7961——源码 docstring 明确记录失败原因：*Mamba 专家在 8³ 短序列（L=512）上分工趋同，稀疏丢弃信息得不偿失*（[v10.py#L17-L18](file:///g:/Codes/Python/SRTP/Essay/PythonFiles/Code/SegResMamba-Lite/models/v10.py#L17-L18)）。日志：`train_v10_2.0mm_20260817_120418.log` / `eval_segresmamba_lite_2.0mm_20260817_184112.log`
2. **改进逻辑**：Mamba 是序列算子，在短序列上各专家感受野趋同；换成 Attention 专家（每专家独有 Q → 天然不同的注意力模式）并把路由细化到 token 级，让「哪里用哪个专家」由数据决定
3. **结果**：LW Dice 0.7961→0.8304（+0.0343），全局 HD95 5.05→4.63，参数量 1.46M→1.42M——三指标同向改善
4. **待补证据**：专家类型与路由粒度两变量同时改变，主效应/交互作用由 2×2 析因（A2/A3，P0）分离；K/N/共享 K/V 的边界由 B/C/D 组界定（[论文实验设计.md §4](实验记录总集.md)）

## 五、一页结论

1. **主榜（LW Dice 均值，全部模型排序）**：**V10 0.8304 为全部正式模型第一**，其后依次 VMUNet 0.8194 > V11 0.8130 > V2 0.8056 > V1 0.8007 > V9 0.7993 > V6 0.7988 > V4 0.7972 > V3 0.7964 > V7 0.7934 > V8 0.7731 > SegResNet 0.7669 > VSSUNet 0.7045；种子变体参照（V10 同结构异种子，非独立模型）：S1 0.8355 / S2 0.8128。区域上 TC/ET 全部第一，WT 0.8410 略低于 VMUNet（0.8509，被对方 20–36 mm 定位劣势抵消，见 Part E.3）。
2. **参数效率**：V10 1.42M = SegMamba 官方（74.87M）的约 1/50、SegResNet（4.70M）的约 1/3.3，全局 Dice 相当/更高、LW 大幅更高。
3. **设计选择全部闭合**：Attention 专家 + token 级 Top-2 路由（A 组严格显著）、4 专家倒 U（C 组双向闭合）、共享 K/V（D 组带内省参）、瓶颈位置（G 组带内）、Top-2 精度-效率最优（B 组）；负载均衡与路由噪声鲁棒（E/F 组）。
4. **两个有价值的负结果**：V12 边界门控（MoA 已隐式覆盖边界功能）、EMA1 真 EMA（LW 尾部劣化，SWA 口径更优）。
5. **方法学护城河**：S1/S2 种子噪声带 ±0.011 为全部判定的统计尺子；batch 两层基准隔离批次混杂；消融「评估-训练」参数量指纹逐条核对。

### 3.5 V6：Soft MoA（4 Mamba 专家 + 样本级软路由，1,463,530 / 1.46M，合规）
- ✅ **全局 HD95 冠军 4.28**，TC 4.05、ET 3.43 均为全系列最低；Dice 0.8904 亚军
- 架构事实（容易被误述，特别澄清）：
  - **只有 4 个 Mamba 专家，没有 DConv 专家，没有 α 参数**
  - 专家异构：d_state = 4/8/16/8，扫描方向 = forward / backward / depth_first / width_first，expand=1
  - 路由器：GAP → MLP(dim→dim/4→4) → Softmax，输出**每个样本一组**软权重；4 专家全部前向加权（soft，非稀疏）
  - 训练时 logits 加 0.1 均匀噪声并重归一化防坍缩；输出带残差 `out + x`；附 KL 负载均衡损失
- 定位：MoA 路线最成功的一版

### 3.6 V7：加入 DConv 专家 + Sigmoid α（1,498,411 / 1.50M，合规，余 1,589 参数）
- ✅ **全局 Dice 冠军 0.8913**，TC Dice 0.8933 全系列最高
- 在 V6 的 4 个 Mamba 专家之外新增 4 个 DConv 专家（DW3³ + PW1×1 + GELU，无 norm，每个约 1K 参数）
- `α = sigmoid(alpha_raw)`，alpha_raw 初值 1.4（α≈0.80 起步，偏向 Mamba）
- **checkpoint 实测**：`moa_8.alpha_raw = 1.3937547 → α = 0.8012`（Mamba 组占约 80%）
- ⚠️ HD95 4.54，比 V6 高 0.26；DConv 组贡献仅约 20%

### 3.7 V8：温度缩放 α（结构同 V7，1,498,411 / 1.50M，合规）
- **网络结构与 V7 完全相同**，唯一差异：`α = sigmoid(alpha_raw / τ)`，alpha_raw 初值 0、τ 初值 1
- α、τ 不参与 EMA，使用 10× 学习率（针对 V7 α 几乎不动的问题）
- ✅ LW HD95 6.09（当时全系列最佳，现仅次于 V9 6.06）
- ❌ LW Dice 0.7731 全系列最低；全局 Dice 0.8860
- α≈0.5005 来自旧实验记录（**V8 权重未留存，无法用 checkpoint 复核**）

### 3.8 α 演进的证据链小结

| 版本 | α 机制 | 初值 | 收敛值 | 证据等级 |

## 4. 各版本架构详解

### 4.1 V1（init_filters=24，实验配置）

```
SegResMamba-Lite V1
├── Stem: Conv3d 4→24 + InstanceNorm + ReLU
├── Encoder
│   ├── Enc1: LightResBlock 24→24（无 SE）
│   ├── Down1: Conv3d stride=2  24→48
│   ├── Enc2: LightResBlock 48→48 + BiMamba @16³
│   └── Down2: Conv3d stride=2  48→96
├── Bottleneck: LightResBlock 96→96 + BiMamba @8³
└── Decoder
    ├── Up2 + cat(x3=x2_mamba @16³)      # 跳跃接 Mamba 输出
    ├── Up1 + cat(x1_down)               # 接 down1 输出
    └── Up0 + cat(x0)
```

### 4.2 V2（init_filters=20；V6–V11 的共同骨架）

```
SegResMamba-Lite V2
├── Stem: 4→20
├── Enc1: LightResBlock 20→20 + BiMamba @32³
├── Down1: 20→40
├── Enc2: LightResBlock 40→40 + BiMamba @16³
├── Down2: 40→80
├── Bottleneck: LightResBlock 80→80 + BiMamba @8³
└── Decoder: Up2+cat(x3_mamba) / Up1+cat(x1_down) / Up0+cat(x0)
```

### 4.3 V3 / V4（init_filters=20）

```
V3                              V4
├── Enc1 + BiMamba @32³ + SE     ├── Enc1 + BiMamba @32³（无 SE）
├── Enc2 + BiMamba @16³ + SE     ├── Enc2 + BiMamba @16³（无 SE）
├── Bottleneck:                  ├── Bottleneck:
│     BiMamba @8³ ×2（残差）+SE  │     BiMamba @8³ ×3（残差）+SE
├── Decoder:                     ├── Decoder:
│     Up2 后 BiMamba @16³ +SE    │     Up2 后 BiMamba @16³ +SE
│     Up1/Up0 常规               │     Up1 后 BiMamba @32³ +SE
└── 跳跃 Up1 接 @32³ Mamba 输出  └── 跳跃 Up1 接 @32³ Mamba 输出
```

### 4.4 V6：Soft MoA Bottleneck（无 DConv、无 α）

```
MoABottleneckV6（替换 V2 的 BiMamba @8³）
├── InstanceNorm(x)
├── 4× MambaExpert（expand=1，全部前向）
│     e0: d_state=4,  forward
│     e1: d_state=8,  backward
│     e2: d_state=16, depth_first
│     e3: d_state=8,  width_first
├── Router: GAP → Linear(80→20) → ReLU → Linear(20→4) → Softmax
│     训练时 logits + U(0,0.1) 后重归一化
├── out = Σ w_i · e_i(x)
└── return out + x                 # 残差
辅助：load_balancing_loss（KL，专家使用频率趋近均匀）
```

### 4.5 V7 / V8：双专家组 + α 融合

```
MoABottleneckV7/V8
├── InstanceNorm(x)
├── Mamba 组：同 V6 的 4 个 MambaExpert → 软路由加权 = mamba_out
├── DConv 组：4× DConvExpert（DW3³ + PW1×1 + GELU）→ 同路由加权 = dconv_out
├── 融合：
│     V7: α = sigmoid(alpha_raw)               # raw 初值 1.4
│     V8: α = sigmoid(alpha_raw / τ)           # raw 初值 0, τ 初值 1, 10×lr, 不入 EMA
│     out = α·mamba_out + (1−α)·dconv_out
└── return out + x
```

### 4.6 V9：稀疏 DConv MoE

```
MoEBottleneckV9
├── InstanceNorm(x)
├── 4× DConvExpert: (k3,d1) (k3,d2) (k5,d1) (k3,d1)
├── Router: GAP → MLP → Softmax（样本级，B×4）
├── TopK(weights, k=2) + 重归一化
├── 逐样本仅前向选中的 2 个专家，加权求和（未选中无计算/无梯度）
└── out + x；get_moe_load_balance_loss()，lb_weight=0.01
```

### 4.7 V10：论文级 token-MoA（现行第二版）

```
MoABottleneckV10（dim=80, 4 experts, top_k=2）
├── 共享: W_k Linear(80→40), W_v Linear(80→80)
├── 4× AttentionExpert: 各自 W_i^q Linear(80→40) + W_i^o Linear(80→80)
│     Attention(Q_i, K_shared, V_shared)
├── Router: Linear(80→4)，token 级（B×L×4，L=8³=512）
├── 每 token Top-2 + 重归一化，仅选中专家在对应 token 上计算
└── out + x
```

### 4.8 V11：边界感知混合 MoA

```
MoABottleneckV11
├── InstanceNorm → BoundaryAttention3D
│     edge = DWConv3×3×3（固定核：中心 −6、26 个邻域各 +1，requires_grad=False）
│     mag  = |edge|.mean(C) / max          # 空间归一化
│     gate = Conv1×1(80→20)→ReLU→Conv1×1(20→80)→Sigmoid
│     x_enh = x · (1 + gate(x) · mag)
├── 共享 W_k/W_v
├── 2× AttentionExpert（独有 Q、W_o）+ 2× DConvExpert（k3d1, k3d2）
├── token 级 Linear 路由；训练 logits += N(0, 0.05²)；Top-2 稀疏
└── out + x（+ 负载均衡损失）
```

## 6. 演进复盘

### Step 1：V1 → V2（多尺度 + 控参数）

| 维度 | V1 | V2 | 说明 |
|------|----|----|------|
| 实验 init_filters | 24 | 20 | 通道缩减（注意：不是签名默认 26→22） |
| BiMamba 尺度 | @16³、@8³ | @32³、@16³、@8³ | 高分辨率层补长程建模 |
| 参数量 | 1.52M（超限） | 1.42M（合规） | −0.10M |
| 全局 Dice / HD95 | 0.8887 / 4.72 | 0.8885 / 4.63 | Dice 持平，HD95 改善 |
| LW Dice / HD95 | 0.8007 / 8.05 | 0.8056 / 7.46 | 病灶级双改善 |

### Step 2：V2 → V3（SE + 残差 + 双 Bottleneck + 解码器 Mamba）

| 维度 | V2 | V3 |
|------|----|----|
| 全局 HD95 | 4.63 | **4.41**（WT 5.37→5.02，ET 3.70→3.59） |
| 全局 Dice | 0.8885 | 0.8853（−0.0032） |
| 代价 | — | 参数 1.42M→1.51M，超红线 |

### Step 3：V3 → V4（加深失败）

HD95 4.41→5.04，参数 1.51M→1.56M。失败原因：

1. **三重 Bottleneck 过拟合**：双重已是深度-性能平衡点，8³ 只有 512 token，第三层 SSM 边际信息极少
2. **SE 策略性放置失效**：编码器去 SE、解码器留 SE 破坏了通道选择的一致性
3. **解码器 Mamba 叠加无收益**：@32³ 共 32,768 token，序列建模成本高、收益低

### Step 4：V6 → V7 → V8（MoA 与 α）

- V6 证明**异构多专家软路由**本身有效（HD95 冠军），它没有 α，只有 4 路 Softmax 权重
- V7 加入 DConv 专家组并用 sigmoid α 融合，Dice 夺冠；α 实测收敛到 0.8012，DConv 组实际只占 20%
- V8 用温度缩放 + 10× 学习率让 α 真正可动，收敛 ≈0.5005，病灶边界改善（LW HD95 6.09）但 LW Dice 跌到 0.7731
- 三条证据共同说明：Mamba 长程建模与卷积局部细化**近等权互补**，过度偏向任一方都有代价

### Step 5：V9 → V10 → V11（稀疏化、token 化、边界化）

- V9 把专家全部换成 DConv 并做**真稀疏**（样本级 Top-2），1.42M 拿到 LW HD95 冠军；三次评估显示该路线训练方差较大（LW HD95 5.84–9.41 摆动）
- V10 先做 Mamba 专家 + 样本级稀疏（LW Dice 0.7961，失败），再严格按 SHMoAReg 改共享 K/V + Attention 专家 + token 级路由，LW Dice 跳到 0.8304——**token 级路由 + 全局注意力是病灶级能力的关键来源**
- V11 加固定边界算子门控与混合专家，LW Dice 0.8130（介于 V2 与 V10 之间），但 WT 全局边界恶化（6.53），显式边界偏置并非免费午餐

## 7. 经验教训（有证据支撑的结论）

1. **关键层放 Mamba 即可**：V2 仅 3 个 BiMamba 层、1.42M 就超过 4.70M 的 SegResNet
2. **双重 Bottleneck 是甜点，三重过拟合**（V3→V4：HD95 4.41→5.04）
3. **SE 必须一致使用**：全量有效（V3），策略性放置失效（V4）
4. **跳跃连接传 Mamba 特征比传原始特征效果好**（V1 起即采用 @16³ Mamba 输出做 skip）
5. **软路由 MoA 提升全局指标**（二代 Dice/HD95 双优），**token 稀疏 MoA 提升病灶级指标**（V10 LW Dice 0.8304）
6. **可学习 α 会偏向容量更强的 Mamba**（V7 → 0.8012）；温度缩放能纠偏，但指标有得有失
7. **小数据集上训练方差真实存在**：V9 同配置三次评估 LW HD95 在 5.84–9.41 间波动，单次结果下结论需谨慎
8. **显式几何先验（边界门控）收益有限**：V11 只在病灶级获益，全局 WT HD95 反被拖累

## 四、显著性判定框架

### 4.1 batch 6 组：种子噪声阈值

以 S1/S2（同结构、seed 0/1）的 LW 均值波动为种子噪声基准：

- 三点（锚点参考 + S1 + S2）极差 **0.0227**；以 S1/S2 均值 0.8242 为中心、极差半宽为容忍带，**LW 均值 < 0.8015 判为低于默认结构的显著差异**（超出种子噪声范围）。
- 全局 Dice 均值在全部实验中仅波动 0.0047（0.8885–0.8932），与种子噪声同量级。
- **该阈值仅适用于 batch 6 组**——阈值由 batch 6 实验的种子噪声建立，跨 batch 使用会引入混杂。

### 4.2 batch 4 组：组内 Δ 判读

B2/D1/G1 与 AB4 的 LW 均值差值 Δ 按以下标准判读（阈值借用 batch 6 组种子噪声带；batch 4 梯度噪声理论上更大，该近似使判定只会更保守，不翻转结论方向——见局限说明）：

- |Δ| ≤ 0.005：噪声量级，与锚点结构无实质差异；
- Δ < −0.01：明显低于锚点结构，该设计选择的必要性成立；
- 介于两者之间：谨慎表述为"趋势性下降"。

### 4.3 batch 4 组对比论证（目的 → 结果 → 证明）

**1. B2 vs AB4 —— Top-4 vs Top-2（稀疏度选择）**
- **目的**：验证 token 级 Top-2 稀疏路由的稀疏度选择——若全激活（Top-4）能显著提升精度，则稀疏性并非关键；若不能，则稀疏选择性是精度-效率平衡的核心。
- **结果**：B2 0.8083 vs AB4 0.8010，**Δ = +0.0073**（介于噪声带与显著阈之间）；Top-4 计算量约为 Top-2 的 2 倍（batch 6 下 22 s/it 完全不可训练）。
- **证明**：Top-4 的精度增益不显著而成本翻倍，**Top-2 为精度-效率最优点**；结合 B1（Top-1 显著低 0.7895）构成稀疏度倒 U 型证据——过稀表达不足、过密稀疏性丢失。

**2. D1 vs AB4 —— 独立 K/V vs 共享 K/V**
- **目的**：验证共享 K/V 设计的必要性——独立 K/V 为每个专家配置独立键值空间（多 2.5 万参数），若精度显著更高则共享仅为省参数的妥协；若相当，则共享兼有效率与正则双重收益。
- **结果**：D1 0.7963 vs AB4 0.8010，**Δ = −0.0047**（噪声带内边缘）。
- **证明**：独立 K/V 未带来精度收益，**共享 K/V 以更少参数达到同等病灶级性能**，且迫使 4 个 Attention 专家在同一 K/V 表示空间内分化——与 C 组容量倒 U 型互证（容量瓶颈在专家数而非 K/V 拆分）。

**3. G1 vs AB4 —— 瓶颈 MoA vs 解码器追加 MoA（位置选择）**
- **目的**：验证 MoA 置于 8³ 瓶颈的位置充分性——若在 16³ 解码器侧追加 MoA 能显著提升病灶级性能，则瓶颈位置不足；若带内，则瓶颈已充分。
- **结果**：G1 0.8018 vs AB4 0.8010，**Δ = +0.0008**（噪声带内，仅为噪声带半宽的 1/6），参数 +48,924。
- **证明**：外扩 MoA 无病灶级增益，**瓶颈 8³ 已充分覆盖全局建模需求**（全局上下文经 skip 连接流向解码器，16³ 侧全局建模与之功能重叠）；「MoA 置于瓶颈」由设计直觉升级为实验证据。

**4. AB4 vs 锚点(6) —— batch 效应量化（仅作参考，不入判定）**
- **目的**：量化 batch 本身对结果的影响，检验两层 batch 基准设计的必要性。
- **结果**：LW 均值 0.8010 vs 0.8153，**差 −0.0143**，远超种子噪声带（半宽 ±0.011）。
- **证明**：batch 对绝对值影响显著，**跨 batch 比较绝对值不可行**——两层基准设计（每组各自同口径锚点）是必要的而非可选的。

## 五、分组分析

### A 组 — 专家类型与路由粒度（MoA 核心设计，batch 6 组全部显著）

- **目的**：验证 MoA 两个核心设计——专家类型（Attention vs Mamba/DConv）与路由粒度（token 级 vs 样本级）——是否均为病灶级性能的必要选择。

- **A3（Mamba 专家）LW 均值 0.7891，batch 6 组最低**：Mamba 序列专家在病灶级分割上明显弱于 Attention 专家。Mamba 的长程序列建模适合全局上下文，但病灶检测需要空间上精确的注意力对齐——支持 V10 选择 Attention 专家。
- **H1（DConv 专家）0.7977 显著低**：纯卷积专家缺乏自适应权重分配，同样劣于 Attention 专家。
- **A2（sample 级路由）0.7995 显著低**：样本级软路由让全部专家等权参与，丢失了 token 级"按需选择"能力；token 级 Top-K 稀疏路由是病灶级性能的关键。
- 结论：**Attention 专家 + token 级路由两个核心选择均被消融证实（严格同口径）**。

### B 组 — Top-K 稀疏度

- **目的**：验证 Top-2 稀疏度是否为精度-效率最优点（对照 Top-1 表达不足与 Top-4 稀疏性丢失）。

- **B1（Top-1）0.7895 显著低（batch 6 组，严格）**：单专家激活表达不足，病灶级 Dice 掉最多（LW WT 0.7844）。
- **B2（Top-4）0.8083，Δ = +0.0073（趋势性，未达显著）**：Top-4 病灶级精度略优于 Top-2（介于噪声带与显著阈之间，谨慎表述），但全激活使计算量约为 Top-2 的 2 倍（batch 6 下 22 s/it 完全跑不动），且稀疏选择性退化。与 B1（Top-1 显著低）共同形成**倒 U 型、Top-2 为精度-效率最优**的完整证据。

### C 组 — 专家容量

- **目的**：定位专家容量的精度最优点（容量过小表达不足、过大稀释专家分化）。

- **C1（2 专家）0.7909 显著低（batch 6 组，严格）**：专家过少容量不足，支持 4 > 2 的容量下界。
- **C2（8 专家）0.7929 显著低（batch 6 组，严格；日志核实其为 batch=6，见口径说明 3）**：专家过多稀释了 token 级路由的稀疏选择性，支持 4 < 8 的容量上界。
- **结论（双向闭合）**：专家容量呈倒 U 型，4 专家为精度最优点；4 > 2 与 4 < 8 均超出种子噪声带严格成立。

### D 组 — K/V 共享

- **目的**：验证共享 K/V 设计的价值（精度与效率的权衡归属）。

- **D1（独立 K/V）0.7963，Δ = −0.0047（噪声带内边缘）**：独立 K/V 与共享 K/V 病灶级精度无实质差异（|Δ| 恰在 0.005 带内边缘，方向为负）。**共享 K/V 的必要性主要体现在效率而非精度**：以约 2.5 万参数的节省达到同等性能，且迫使 4 个 Attention 专家在同一 K/V 表示空间内分化——与 C 组容量倒 U 型互证（容量瓶颈在专家数而非 K/V 拆分）。

### E 组 — 负载均衡权重（不敏感，趋势可见）

- **目的**：验证负载均衡权重默认 0.01 的合理性（过大约束是否损害专家分化）。

- E1 (0) / E2 (0.001) / E3 (0.05) 中，E1/E2 落于噪声带内，E3 (0.7994) 显著低：lb_weight 过大（0.05）会过度约束路由分布、压缩专家分化空间。
- 组内趋势 E2 (0.8053) ≈ E1 (0.8047) > E3 (0.7994)：默认 0.01 合理。

### F 组 — 路由噪声（不敏感）

- **目的**：验证训练期路由噪声的必要性（默认 0 配置是否可保持）。

- F1（0.05）0.8046 带内：训练期路由噪声对结果影响有限，默认 0（V10 配置）可保持。

### S 组 — 种子稳定性

- **目的**：建立种子噪声基准，为全部显著性判定提供统计度量衡。

- S1 0.8355 / S2 0.8128：同结构种子间波动 ±0.011（半宽 0.0114），构成 batch 6 组全部判定的噪声基准。
- 含义：**单种子差异 < 0.02 的实验不可下结论**；本报告中所有"显著"判定均满足超出该噪声带。

### G 组 — 解码器侧 MoA

- **目的**：验证 MoA 置于 8³ 瓶颈的位置充分性（外扩至 16³ 解码器是否有增益）。

**G1 0.8018，Δ = +0.0008（噪声带内）**：解码器侧追加 16³ MoA 无病灶级增益（Δ 仅为噪声带的 1/6，稳稳带内），参数却增加 48,924。机理解释：8³ 瓶颈已聚合全局上下文并经 skip 连接流向解码器，16³ 侧的全局建模与之功能重叠，边际增益趋零。**该负结果把「MoA 置于瓶颈」从设计直觉升级为实验证据**——瓶颈是 MoA 的充分位置（外扩无增益），结合 A 组（瓶颈内任何替换均显著更差）构成位置选择的完整论证。

## 七、总体结论（当前证据等级）

### 通俗结论一览（快速版，专业论证见下文与第五节）

| 消融组 | 大白话结论 | 证据强度 |
|--------|-----------|---------|
| A 专家+路由 | MoA 的两个核心设计（Attention 专家 + 每个位置自己挑专家）缺一不可，换掉哪个都明显变差 | 严格显著 |
| B 稀疏度 | 每个位置「问 2 个专家」最划算：只问 1 个不够用，问 4 个又贵又没明显提升 | 严格（左臂）+ 趋势（右臂） |
| C 专家数 | 4 个专家刚刚好：2 个不够用，8 个互相拖累——两个方向都严格验证（倒 U 型闭合） | 严格显著（双向） |
| D 共享 K/V | 专家共用一套「字典」精度无损，还省 2.5 万参数 | 带内（等效，优势在效率） |
| E 负载均衡 | 别强制专家轮流干活：管得太严反而变差，默认值刚好 | E3 严格显著，E1/E2 带内 |
| F 路由噪声 | 训练时加随机扰动没什么用，不加就行 | 带内 |
| G MoA 位置 | MoA 放瓶颈层就够了：解码器再加一层纯属浪费参数 | 带内（无增益） |
| S 种子 | 换个随机种子性能会波动 ±0.011——这是所有「显著/不显著」判断的尺子 | 噪声基准 |
| V12 边界门控 | 显式建模边界失败：MoA 已隐式覆盖该功能（有价值的负结果） | 严格判定不通过 |

**一句话总结**：V10 的每一个设计选择都被实验证明是最优的，且没有任何变体（8 专家、Top-4、独立 K/V、解码器外扩、边界门控）能在各自同口径对比中显著超越它。

---

1. **已被严格证实的必要性（batch 6 组，同口径阈值判定）**：Attention 专家（vs Mamba/DConv）、token 级 Top-2 路由（vs sample 级）、专家容量 4>2（C1）与 4<8（C2，倒 U 型闭合）、极端负载均衡有害（E3）——替换为任一次优选择均使 LW Dice 显著下降 0.02–0.04，超出种子噪声带。
2. **batch 4 组组内判定（全部闭合，无一条达到必要性标准）**：共享 K/V vs 独立 K/V（D1，Δ=−0.0047 带内——共享的优势在效率）、Top-2 vs Top-4（B2，Δ=+0.0073 趋势性——Top-4 精度不显著更优而计算翻倍）、解码器侧追加 MoA（G1，Δ=+0.0008 带内——瓶颈位置充分）。
3. **鲁棒性证据（batch 6 组）**：负载均衡权重（E1/E2）与路由噪声（F1）在合理范围内不敏感，说明 MoA 不依赖精细超参调优。
4. **性能-效率最优点**：Top-2 稀疏路由以 Top-4 一半的计算量取得不显著劣于（趋势上略优）的病灶级精度（B2 Δ=+0.0073），支撑论文的轻量化主张（<1.5M 参数，约为官方 SegMamba 的 1/50）。
5. **区分度来自病灶级指标**：全局 Dice 对 MoA 设计不敏感（骨干网络主导，全组极差仅 0.0047），而 LW Dice 的组间极差达 0.046——证明 MoA 路由设计主要作用于小病灶/多病灶检出，与论文"MoA 提升病灶级敏感性"的主张一致。
6. **V10 为最终模型**（A–G 全部消融闭合，无任何变体在各自口径内显著超越默认结构）；V12 边界门控为探索性负结果。

### 局限与说明（论文需注明）

- 锚点为 2026-08 代码历史评估，与 9 月消融代码存在 0.27% 参数差与口径差；论文中建议以 S1/S2 作为默认结构基准（或补一次 9 月代码 seed 42 重训）。
- **两层 batch 基准设计**：因 8GB 显存限制，B2/D1/G1 采用 batch=4，与锚点(6) 之间不做直接对比；该组结论以同 batch 基准 AB4 的组内 Δ 为准。其余实验与锚点同为 batch=6，阈值判定严格同口径。batch 效应经 AB4 vs 锚点(6) 量化为 −0.0143（远超噪声带），证明禁止跨组比较绝对值是必要的。
- 每个配置单种子单次训练；种子噪声基准（±0.011）由 S1/S2 估计，样本量有限。
- batch 4 组 Δ 判读阈值借用 batch 6 组种子噪声带（S1/S2），batch 4 梯度噪声理论上更大；该近似使判定只会更保守（B2 的趋势性优势可能仅为噪声），不翻转任何结论方向。

## 一、最终模型确定：V10（Attention 版）

### 1.1 候选对比（全部为已完成的 188 例测试集结果，seed=42）

| 候选 | 参数量 | 全局 Dice | 全局 HD95 | LW Dice | LW HD95 | 定位 |
|------|-------:|:--------:|:--------:|:-------:|:-------:|------|
| V6 | 1.46M | 0.8904 | **4.28** | 0.7988 | 7.28 | 全局 HD95 冠军（4 Mamba 专家样本级软路由，无 α） |
| V7 | 1.50M | **0.8913** | 4.54 | 0.7934 | 7.76 | 全局 Dice 冠军（α=0.8012，Mamba 主导） |
| V9 | 1.42M | 0.8893 | 4.73 | 0.7993 | **6.06** | LW HD95 冠军（Top-2 稀疏 DConv MoE） |
| **V10（Attention 版）** | **1.42M** | 0.8878 | 4.63 | **0.8304** | 6.39 | **LW Dice 冠军 → 选定** |
| V11 | 1.44M | 0.8879 | 5.01 | 0.8130 | 6.80 | 边界感知版，各项全面次于 V10 |

### 1.2 选定理由

1. **临床核心指标最优**：BraTS 评审最看重的 lesion-wise Dice 全系列最高（0.8304），逼近 VMUNet 0.8354，而 LW HD95 仅 6.39（VMUNet 33.09）——小病灶检测能力与定位精度兼得
2. **全局指标处第一梯队**：Dice 0.8878 与 V7 仅差 0.0035（188 例测试集的噪声量级内），HD95 4.63 与 V2 持平
3. **参数量最小档**：1.42M，与 V2/V9 并列最小合规版本（<1.5M）
4. **方法论叙事最强**：严格实现 SHMoAReg（arXiv:2509.20073）的论文级 MoA——共享 K/V + 独有 Q/W_i^o 专家 + token 级 Top-K 稀疏路由，公式完整、消融空间大
5. V10 的源码已内置路由权重/Top-K 索引接口（`get_moa_route_weights` / `get_moa_topk_indices`），路由可视化零改动

### 1.3 备选与风险预案

- **若审稿人强调全局 Dice**：并列报告 V7（0.8913）作为「全局最优变体」；V7 与 V10 共享同一 V2 骨干，叙事不冲突
- **若 §4-A 析因中「Attention 专家 + 样本级路由」（A2）反超 V10**：说明 V10 的跃升主要来自专家类型而非路由粒度，最终模型需重议（预期概率低）
- **若 §4-I 的 V12（V10+边界门控）LW Dice > 0.8304**：V12 升级为最终模型，并补跑稳定性流程（§6）

- **判据**：I1 LW Dice > 0.8304 → V12 替代 V10 成为最终模型（重走 §6 稳定性流程）；≤ 0.8304 → 论文结论「边界门控在 Attention 专家体系下无增益」，V11 回退归因于专家池替换
- **代码改动**：注册 v12（从 v11.py 移植 BoundaryAttention3D 到 v10 骨干）

## 八、执行顺序与算力预算

| 优先级 | 内容 | 训练次数 | 预估 GPU 时 |
|--------|------|:--------:|:-----------:|
| P0 前置 | 环境检查（mamba_ssm）+ 代码改动 + 自检；环境不符则加跑锚点 | 0–1 | 0–5 h |
